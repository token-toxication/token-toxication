## 目标与已确认决策

- 面向自用/开源项目的日常运维，一眼回答：是否正常、哪里变慢、Token 用在哪里。
- 用户指定 ECharts，并选择「SQLite 历史聚合看板」，不引入独立监控服务。
- 增强现有 Overview，不另建一个重复的 Dashboard；本轮交付设计，不包含实现、提交或部署。

## 现有基础与前提

- `dashboard.tsx` 有概览卡片和手写 SVG 请求趋势；`db.rs` 已按 5 分钟聚合最近约一小时的日志。
- `request_logs` 保存状态码、模型/账号、耗时、TTFT、排队时间、输出速度、Token 和重试元数据；每行代表一次已结束的上游尝试，不一定是一个用户请求。
- `RelayMetrics` 的 transport/outcome/retry 等计数只存在内存中，重启清零，不能充当历史时间序列。
- 旧设计审计已指出趋势图应使用真实时间桶，不能为了图形平滑编造数据；继续保持这一点。

## 第一版界面

保留现有 Provider pool 和最近日志。在 Overview 增加统一时间范围（1h / 24h / 7d）、模型/账号筛选、后台自动刷新与最近更新时间。

| 区域 | 图形与内容 |
| --- | --- |
| 概览 | 已结束尝试数、成功尝试率、TTFT P95、总 Token、缓存命中率 |
| 流量与结果 | 成功、失败、客户端取消、服务关闭、未知结果的堆叠柱；错误分类显示 429、replay、turn-state 等计数 |
| 响应性能 | TTFT 与上游尝试耗时分别展示 P50/P95；排队耗时单独展示，不冒充完整用户端延迟 |
| 输出速度 | 成功且有有效 OTPS 的样本中位数，单位 token/s，标明样本数 |
| Token 与缓存 | 缓存输入、非缓存输入、输出的堆叠柱；缓存命中率独立小图，不用混合单位双轴 |
| 模型/账号对比 | 横向条形排行，按尝试数、Token、失败尝试数切换，最多 Top 10 + 其他 |
| 运行期诊断 | transport、重试尝试、内部 overload 重试、会话亲和和选路拒绝；与历史图分区，标明「自服务启动以来」 |

## 统计契约

- 历史图以完成时间归桶，标题明确是「已结束尝试」，不是到达速率或活跃并发。不展示用户请求级最终成功率；只有完整请求终态才能支持该口径，不能用最后一条已记录 attempt 猜测。
- 失败、客户端取消和服务关闭分别显示。成功尝试率为 success / 已知结果尝试数，取消及关闭也在分母中；未知结果另列并同时展示已知覆盖率。该指标不声称代表服务可用率。
- TTFT、尝试耗时与 OTPS 只计算成功且字段有效的样本；P50/P95 使用 nearest-rank，null/缺失数据不变成零。返回各自样本数。
- 缓存命中率 = SUM(cached input) / SUM(input)，不能平均各请求的百分比。缓存命中率与缓存/非缓存拆分共同只使用 usage_complete=true 且 0 <= cached input <= input 的有效样本；缓存缺失不能当作未命中。其余已记录输入单列「未分类输入」，显示有效样本数及输入量覆盖率，分母为零时显示无可用样本。
- 总 Token = input + output，cached input 是 input 的子集，不重复相加。总量可汇总所有已记录用量，但不能把其中未知计量的 input 隐式用于缓存命中率分母。
- 使用现有 usage_complete 标记区分完整计量和部分/未知计量；显示已记录 Token 与计量覆盖情况，不把缺失计量当作零消耗。
- attempt_index > 0 的重试尝试与 overload_retry_count 单独统计，不盲目求和，不把尝试次数当作重试用户请求数。
- 时间范围由服务端当前时间确定，返回 UTC 边界，界面显示本地时间及时区。当前未完成时间桶明确标注；空桶补零，但缺失性能样本保留 null。
- 路由选择前的拒绝目前不写入请求日志，只在运行期诊断展示，明确不在历史尝试统计中。费用字段目前固定写零，第一版不展示费用估算。

## 数据与接口

- 新增管理员鉴权的聚合接口，例如 `GET /admin/api/analytics`，复用现有 OpenAPI/SDK 生成流程。仅接受预设范围和有界模型/账号筛选，使用参数化 SQL。
- 1h 使用 1 分钟桶，24h 使用 5 分钟桶，7d 使用 1 小时桶；最多 288 桶。排行最多 10 项加「其他」，响应不包含逐条日志或原始错误内容。
- 历史记录增加可空的 transport 和 bounded outcome 列，在现有记录入口持久化已经算出的元数据。迁移保留旧数据，无法确定的字段为 unknown；不从 path 或 stream 标志猜测 WebSocket。
- 旧数据仍可用于尝试量、状态码和 Token 聚合；分类统计、性能成功样本与 transport 查询显示其可用覆盖范围，不把新增列缺失说成零错误。
- 历史聚合始终按稳定的 provider_account_id 分组，不因账号已删除而丢弃日志；账号名称采用 LEFT JOIN，缺失时显示「已删除账号」和短 ID。筛选项包含所选时间范围内的历史账号，采用有界分页/搜索，不只使用现存账号列表；无账号归属的记录单列「未分配」。筛选、排行 Top 10 + 其他与总量使用同一数据集。
- 运行期诊断单独返回 startedAt 和 snapshotAt，不套用历史范围/模型/账号筛选，并在界面明确提示这一点。
- 聚合在后端完成，不下载最近 50 条或全部日志计算统计。限制并发重复查询，按范围/筛选合并并短暂缓存；工程设计中确定非阻塞查询及读连接方案，避免长查询持有 relay 的共享数据库写入锁。

## ECharts 集成

- 按需引入 `echarts/core`、所需图形/组件和渲染器，图表模块延迟加载；不引入第二套 UI 组件体系。
- 复用现有 shadcn 卡片、主题和 Lingui 翻译；明暗主题都可读。ResizeObserver 调整大小，卸载释放 observer 和 chart 实例。
- 默认约 15 秒刷新聚合数据，仅在 Overview 可见时刷新；不重复请求整个管理工作区，不闪白或重置用户筛选。缓存与请求均以范围/模型/账号为查询键；相同键刷新失败时保留该键快照并标明陈旧状态和实际时间边界。切换到没有成功快照的新键时隐藏旧图，显示加载或错误，绝不在新筛选标签下复用旧键数据；忽略迟到的旧键响应。
- 减少动态效果，支持 reduced-motion；提供可访问的文字摘要/数据表，不只依赖颜色和鼠标悬停。
- 模型与账号名视为不可信文本，tooltip 使用不插入用户 HTML 的方式。

## 已比较的方案

- 仅图表化现有接口：用户未选择，因为不能提供完整历史的性能/用量趋势。
- SQLite 后端聚合 + ECharts：用户已选择，复用现有日志且无需额外部署组件。

## 验收与下一步

1. 先落实统计契约、迁移与聚合 API，再生成 SDK 和实现 ECharts 看板。
2. 测试成功/失败/取消、重试、跨桶边界、空窗口、未知旧数据、缺失缓存字段/部分计量、cached input > input、零分母及排名归并；固定样本验证分位数。删除账号后，历史总量、排行与历史账号筛选仍一致。
3. 验证管理员鉴权、响应字段隐私、筛选与运行期数据隔离、并发刷新以及查询计划/生产规模日志下的开销，不让看板拖慢 relay。
4. 浏览器验证明暗主题、窄屏、无数据/错误/陈旧状态、主题切换、尺寸变化和资源清理；点击刷新不丢失时间范围，切换筛选后失败不显示其他筛选的旧图，迟到响应不覆盖当前图。
5. `just ci` 通过，并在单独获得部署授权后部署。第一版不包含新监控基础设施、告警、费用结算或 OpenCode 全局配置修改。

## 待工程设计确定

- 聚合查询的读连接、缓存失效和执行时间上限，以及所需索引，以实际查询计划和规模测试决定；不能直接在现有 async DB mutex 内增加长时间扫描。

## 会话观察

- 用户说「OpenCode 基本上可用了」后提出使用 ECharts，当前重点是运行可见性，不是再改客户端协议。
- 用户选择历史聚合而非只换图表库，统计可信度是这次设计的优先级。
